# Enrichment operational robustness
Objective: run attraction enrichment independently from the web process with durable retry state and operational visibility.
Branch: iteration-3-dashboard. Delivery: inline slices. Test runner: Vitest, typecheck, lint, Next build, Docker Compose.

## Specs
1. **S1 — Independent worker**: User request: "venga vamos por el punto 1 robustez operativa". Acceptance: enrichment no longer depends on a web request or Next.js process lifetime; Docker runs a separate worker process sharing the database volume.
2. **S2 — Durable state and retries**: Acceptance: pending, retry, processing, done, and failed states remain in SQLite; worker restarts recover incomplete work without resetting attempts on every polling cycle.
3. **S3 — Observability**: Acceptance: worker logs start, completion, failure, retry, and heartbeat information; a healthcheck detects a stopped or stale worker.
4. **S4 — Safety**: Acceptance: web and worker do not process the same park concurrently inside one process; existing user data is preserved; external failures remain bounded by retry/backoff.
